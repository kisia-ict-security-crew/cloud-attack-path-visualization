# Provenance Graph and Attack Reconstruction

Provenance Graph를 이용해 공격 관련 이벤트를 탐지하고, 전체 공격 흐름을 재구성하는 연구를 정리합니다.

**목차**  
- SLEUTH
- MGDA



<br>

## SLEUTH

### 기본 정보

- 제목: **SLEUTH: Real-time Attack Scenario Reconstruction from COTS Audit Data**
- 발표: USENIX Security 2017
- 원문: [SLEUTH PDF](https://www3.cs.stonybrook.edu/~stoller/papers/sleuth2017.pdf)

### 연구 목적

대규모 감사 로그에서 공격과 관련된 이벤트를 실시간으로 식별하고, 공격의 시작점과 이후 영향 범위를 하나의 흐름으로 재구성하는 것을 목적으로 합니다.

### 핵심 내용

SLEUTH는 운영체제 감사 로그를 프로세스, 파일, 네트워크 객체 간 의존관계 그래프로 변환합니다.

그래프의 주체와 객체에는 신뢰도와 기밀성에 관한 태그가 부여됩니다. 이후 정보가 이동하거나 프로세스가 다른 객체를 사용할 때 태그를 전파하여 의심스러운 정보 흐름을 식별합니다.

탐지된 이벤트는 그대로 나열하지 않고, 공격의 주요 단계와 영향 범위를 확인할 수 있도록 비교적 작은 공격 그래프로 재구성합니다.

### 주요 특징

- 로그를 의존관계 그래프로 변환
- 신뢰도와 기밀성 태그를 이용한 공격 탐지
- 공격 시작점과 영향 범위 분석
- 대규모 로그에서 공격 관련 경로만 선별
- Windows, FreeBSD, Linux 환경을 대상으로 평가

### 프로젝트에서 참고할 점

SLEUTH는 현재 연구와 가장 직접적으로 연결되는 참고 논문입니다.

다만 SLEUTH의 태그는 운영체제 수준의 프로세스와 파일을 중심으로 설계되어 있으므로, 프로젝트에서는 이를 다음과 같이 클라우드에 맞게 다시 정의할 수 있습니다.

- 침해가 확인된 IAM User 또는 세션에 침해 태그 부여
- `AssumeRole`로 생성된 임시 세션에 태그 전파
- Lambda 호출 이후 실행 Role의 행위까지 연결
- 중요 S3 객체나 데이터에 민감도 태그 부여
- N2SF의 데이터 등급을 민감도 태그로 활용
- 침해 태그와 민감도 태그가 만나는 경로를 우선 조사 대상으로 표시

SLEUTH의 방식을 그대로 구현하기보다는, 클라우드에서 발생하는 자격 증명과 실행 문맥 전환을 어떻게 태그 전파 규칙으로 표현할지 참고하는 것이 중요합니다.

## MGDA

### 기본 정보

- 제목: **MGDA: A Provenance Graph-Based Framework for Threat Detection and Attack Scenario Reconstruction**
- 게재: Computer Networks
- DOI: `10.1016/j.comnet.2025.111806`

### 연구 목적

Provenance Graph를 이용해 은밀하게 진행되는 다단계 공격을 탐지하고, 탐지 결과를 분석가가 이해할 수 있는 공격 시나리오로 재구성하는 것을 목적으로 합니다.

### 핵심 내용

MGDA는 단순 규칙 탐지에만 의존하지 않고, 여러 관점의 그래프 정보를 학습하는 자기지도 방식의 그래프 오토인코더를 사용합니다.

이 과정에서 그래프의 구조적 특징과 의미적 특징을 함께 학습하여 기존에 정의되지 않은 공격이나 은밀한 이상 행위를 탐지하려고 합니다.

공격 재구성 단계에서는 다음 두 정보를 결합합니다.

- 주변 이벤트와의 문맥
- 미리 정의된 공격 패턴 규칙

이를 통해 개별 로그 이벤트를 단순히 이어 붙이는 것이 아니라, 공격 단계와 목적을 포함한 상위 수준의 공격 시나리오 그래프를 생성합니다.

### 주요 특징

- 자기지도 방식의 위협 탐지
- 그래프의 구조와 의미를 함께 분석
- 문맥 분석과 규칙 기반 패턴 매칭 결합
- 저수준 이벤트를 상위 수준 공격 단계로 변환
- 탐지 결과를 설명 가능한 시나리오 그래프로 제공

### 프로젝트에서 참고할 점

CloudTrail 이벤트를 모두 같은 수준으로 표현하면 그래프는 생성할 수 있지만, 조사자가 공격의 의미를 바로 이해하기는 어렵습니다.

MGDA의 접근을 참고하면 다음과 같은 이벤트를 하나의 상위 공격 단계로 묶을 수 있습니다.

```text
ListRoles
→ GetRole
→ AssumeRole
```

예를 들어 첫 번째 흐름은 권한 탐색 및 Role 전환, 두 번째 흐름은 서버리스 함수를 이용한 데이터 접근과 같은 시나리오로 표시할 수 있습니다.

다만 MGDA의 학습 모델 전체를 초기 연구 범위에 포함하기보다는, 문맥과 규칙을 이용해 여러 CloudTrail 이벤트에 상위 의미를 부여하는 재구성 방식을 우선 참고하는 것이 현실적일 것 같습니다.
