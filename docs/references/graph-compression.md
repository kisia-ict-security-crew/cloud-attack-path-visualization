# Graph Compression

대규모 감사 로그와 Provenance Graph를 효율적으로 저장하고 조회하기 위한 그래프 압축 연구를 정리합니다.

**목차**
- SEAL

## SEAL

### 기본 정보

- 제목: **SEAL: Storage-efficient Causality Analysis on Enterprise Logs with Query-friendly Compression**
- 발표: USENIX Security 2021
- 원문: [SEAL 공식 페이지](https://www.usenix.org/conference/usenixsecurity21/presentation/fei)

### 연구 목적

대규모 시스템 로그에서 만들어지는 인과관계 그래프의 저장 공간을 줄이면서도, 기존과 동일한 분석 결과를 얻을 수 있도록 하는 것을 목적으로 합니다.

### 핵심 내용

시스템 로그에는 동일하거나 반복되는 행위가 매우 많이 포함됩니다. SEAL은 이러한 이벤트가 구성하는 인과관계 그래프를 분석하여 중복되는 엣지와 구조를 압축합니다.

압축된 데이터를 조회할 때는 필요한 부분만 선택적으로 복원합니다. 전체 그래프를 먼저 복원하지 않기 때문에, 저장 공간뿐 아니라 일부 질의의 처리 시간도 줄일 수 있습니다.

SEAL은 손실 압축을 통해 중요하다고 판단한 이벤트만 남기는 방식이 아니라, 원본과 동일한 질의 결과를 반환하도록 설계된 무손실 압축 방식입니다.

### 주요 특징

- 인과관계 그래프 기반 로그 압축
- 원본과 동일한 질의 결과 유지
- 필요한 부분만 선택적으로 복원
- 저장 공간 절감
- 압축 상태에서 효율적인 조회 지원

### 프로젝트에서 참고할 점

CloudTrail 로그를 그대로 그래프로 변환하면 다음과 같은 반복 이벤트 때문에 그래프가 빠르게 커질 수 있습니다.

- 동일한 세션의 반복적인 조회 API
- 주기적으로 실행되는 Lambda 함수
- 동일 리소스에 대한 반복 접근
- 정상 모니터링 또는 자동화 서비스의 API 호출
- 같은 형태로 반복되는 정상 워크로드

따라서 그래프 시각화 단계에서는 중복 이벤트를 축약할 필요가 있습니다.

다만 SEAL은 저장 효율성과 정확한 질의 결과 보존을 위한 무손실 압축 연구입니다. 발표 화면에서 공격 흐름을 단순하게 보여주기 위한 시각적 축약과는 목적이 다릅니다.

따라서 두 방식을 구분하여, 저장방식을 고려할 때 함께 참고하는 것이 좋을 것 같습니다.
