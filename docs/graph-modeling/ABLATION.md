# CloudTrail 그래프 모델의 최소 스키마 — 절제 실험

> **한 줄 요약**: CloudTrail 로그를 그래프로 옮길 때 무엇을 남기고 무엇을 버려야
> 하는가를, 공격 기법 재현율을 기준으로 측정했다. **필드 하나(`readOnly`)가
> 5개 기법 중 4개를 좌우**하고, 네 개 필드는 빼도 재현율이 그대로다.

---

## 1. 문제

CloudTrail 레코드 하나에는 수십 개 필드가 있고, `requestParameters` 는 API 마다
구조가 다르다. 그래프로 옮길 때 "무엇을 남길 것인가"에 원칙이 없으면 **새 로그가
들어올 때마다 파서에 예외 처리를 덧붙이게 된다.** 실제로 본 연구에서도 기법 로그를
추가할 때마다 추출 규칙이 늘었다.

이 문제를 공학이 아니라 **측정**으로 다룬다. 필드를 하나씩 빼면서 **공격 기법이
그래프에서 여전히 식별되는지** 본다. 안 깨지면 그 필드는 (적어도 현재 분석 목적에는)
필요 없다.

---

## 2. 실험 설계

### 2.1 데이터

Stratus Red Team 으로 생성한 AWS 공격 기법 로그 6종, 총 661 이벤트.
단일 계정, 시간 구간이 서로 겹치지 않는다.

| 기법 | MITRE | 이벤트 | 노드 | 엣지 |
| :--- | :--- | ---: | ---: | ---: |
| credential-access.ec2-steal-instance-credentials | T1552.005 | 183 | 45 | 258 |
| lateral-movement.ec2-instance-connect | — | 302 | 50 | 413 |
| exfiltration.ec2-share-ebs-snapshot | — | 20 | 4 | 22 |

원본 JSON 1,056KB → CSV 270KB (**26%**). 그래프 변환은 데이터를 늘리는 게 아니라
줄인다.

### 2.2 측정 도구 — 기법을 '부분그래프 모양'으로 정의한다

재현율을 재려면 "기법이 식별됐다"의 기준이 필요하다. **API 이름 목록이 아니라
부분그래프 모티프로 정의했다.** 이름 목록은 탐지 룰이지 그래프가 필요 없고, 변종을
못 잡기 때문이다.

| 모티프 | 모양 | 쓰는 필드 | API 이름 |
| :--- | :--- | :--- | :---: |
| **M1** 자격증명 탈취 | 주체가 남의 워크로드를 장악 + 그 워크로드의 자격증명이 같은 출처 IP 에서 쓰임 | `RUNS_ON`, `sourceIP`, `readOnly` | 없음 |
| **M2** 측면 이동 | 한 주체가 남의 워크로드 **둘 이상**에 원격 접근 주입 | `eventSource`, `readOnly`, `RUNS_ON` | 없음 (서비스명) |
| **M3** 유출 | 저장 자산이 CREATE → MODIFY → DELETE 를 다 받음 | `actionL2`, `resourceType` | 없음 |
| **M4** 방어 회피 | 주체가 **관측 자산**(트레일·플로우로그)을 삭제 | `actionL2`, `resourceType` | 없음 |
| **M5** 지속성 | 주체가 남의 신원에 **만료 없는** 자격증명을 발급 | `OBTAINS`, `kind` | 없음 |

**M4 는 서로 다른 두 기법을 하나의 모양으로 잡는다.** `cloudtrail:DeleteTrail` 과
`ec2:DeleteFlowLogs` 는 서비스도 API 도 다르지만 "관측 자산을 지운다"는 모양이
같다. 5개 중 4개가 API 이름을 전혀 쓰지 않는다.

> **순환 논리 회피**: 모티프는 파서 출력이 아니라 기법별 상세 문서(`detail_md/`)의
> 공격 설명·MITRE 매핑·"결정적 이벤트" 항목을 먼저 읽고 도출했다. 정답 건수도 그
> 문서에서 가져왔다. 파서가 잡는 것을 보고 모티프를 짜면 자기충족적 결과가 된다.

### 2.3 절제 축

**축 A — 대상 추출 강도.** 그래프의 대상 노드를 얼마나 열심히 찾는가.

| 레벨 | 방법 |
| :--- | :--- |
| L0 | `resources[]` 배열만 (선행 모델 수준) |
| L1 | + ARN·AWS 식별자 정규식 (**규칙 2개, API 개수와 무관**) |
| L2 | + 핵심 이름 키 6개 |
| L3 | + 전체 키 화이트리스트 50개 (현행) |

**축 B — 필드 하나씩 빼기(leave-one-out).** L3 에서 각 요소를 하나만 끈다.

## 3. 결과

### 3.1 축 A — 추출 강도

| 레벨 | 노드 | 엣지 | 미해결% | CSV | M1 | M2 | M3 | M4 | M5 |
| :--- | ---: | ---: | ---: | ---: | :-: | :-: | :-: | :-: | :-: |
| L0 | 66 | 683 | 77.0% | 141K | ○ | ✗ | ✗ | ✗ | ○ |
| L1 | 117 | 840 | 14.4% | 226K | ○ | ○ | ○ | ✗ | ○ |
| L2 | 118 | 854 | 8.1% | 235K | ○ | ○ | ○ | ✗ | ○ |
| **L3** | **121** | **882** | **6.9%** | **244K** | ○ | ○ | ○ | ○ | ○ |

*○ 정답 일치, ✗ 놓침. '미해결%' 는 대상을 특정하지 못해 서비스 노드로 수렴한 엣지 비율.*

**정규식 2개(L1)만으로 5개 중 4개가 잡힌다.** 키 화이트리스트 50개를 다 넣어도
추가로 잡히는 건 M4 하나뿐이고, **그 하나는 규칙 한 줄 때문이다** — `DeleteTrail`
이 트레일을 `requestParameters.name` 이라는 맨 키로 지정한다. `DeleteFlowLogs` 는
`fl-…` 형태라 정규식이 이미 잡는다.

즉 **"API 마다 추출 규칙을 늘려야 한다"는 압박은 근거가 없다.** 값의 형태로 잡는
규칙(정규식)은 API 개수와 무관하게 고정이고, 이름으로 자산을 지정하는 소수 API 만
따로 다루면 된다.

반면 **L0 는 명확히 부족하다.** 미해결 77%, 5개 중 2개만 식별. `resources[]` 만
보는 설계로는 그래프 기반 분석이 성립하지 않는다.

### 3.2 축 B — 필드 하나씩 빼기

| `OBTAINS` (발급된 자격증명) | 120 | 872 | 241K | ○ | ○ | ○ | ○ | **✗** |

**필드 중요도**

| 깨지는 모티프 수 | 필드 |
| ---: | :--- |
| **4** | `readOnly` |
| 1 | `sourceIP`, `RUNS_ON`, `OBTAINS`, `responseElements` |
| **0** | `ISSUES`, `errorClass`, `resources[]`, `refPath` |

**`readOnly` 하나가 5개 중 4개를 좌우한다.** 이 값으로 "리소스를 바꿨는가(CONTROL)"
와 "조회만 했는가(OBSERVE)"가 갈리고, 네 모티프가 전부 그 구분 위에 서 있다.
AWS 가 모든 이벤트에 직접 붙여주는 불리언 하나가, 서비스별 지식 없이 400개 서비스의
수천 API 를 두 갈래로 나눈다는 뜻이다.

그다음은 **관계 필드**다. `RUNS_ON`(자격증명↔워크로드 바인딩)과 `OBTAINS`(발급된
자격증명)은 각각 한 모티프의 전제이고, 빠지면 그 기법이 그래프에서 **통째로**
사라진다. 둘 다 CloudTrail 이 직접 주는 관계이지 추론이 아니다.

## 4. 논의

**설계 정당화.** "CloudTrail 을 그래프로 옮기려면 결국 전부 넣어야 하는 것 아닌가"
라는 우려에 대해, 이 실험은 **아니라고 답한다.** 5개 기법을 식별하는 데 필요한 것은
정규식 2개 + 이름 키 소수 + 봉투 필드 5개(`readOnly`, `sourceIP`, `eventSource`,
`actionL2` 근거, 관계 2종)뿐이다. 나머지는 **현재 분석 목적에는** 기여가 없다.

**"기여 0"이 "쓸모없음"은 아니다.** `errorClass` 는 권한 정찰 뷰(`DENIED_ATTEMPT`)
의 전제이고, `refPath` 는 "이 참조가 대상인지 질의 조건인지"의 판단을 뷰로 미루기
위한 출처 정보다. 둘 다 이번 모티프 5개가 안 쓸 뿐이다. **이 실험이 주는 것은
'필드를 지우라'가 아니라 '필드마다 어떤 분석이 그것을 요구하는지 밝히라'는 규율이다.**
새 필드를 추가할 때 던질 질문이 "로그에 있는가"에서 **"어떤 모티프가 이것을
요구하는가"** 로 바뀐다.

**부수 발견 — 파서 결함 두 건.** 실험 준비 중 확인했다. (i) 대상의 타입 힌트가
호출부에서 누락되어 같은 IAM 자산이 두 노드로 갈라지고 있었다(5건). (ii)
`iam:CreateAccessKey` 가 발급한 영구 키(`AKIA…`)는 ARN 도 AWS 식별자 패턴도 아니라
어떤 추출 경로로도 잡히지 않아, **T1098 의 결정적 산출물이 그래프에 없었다.** 둘 다
수정 후 위 결과를 얻었다. 모티프를 기준으로 삼으니 결함이 드러난 사례다.

## 5. 한계

**정답이 기법당 1~2건이라 재현율이 계단함수다.** 통계적 의미는 약하고, 이 결과는
"방법이 성립하는가"를 보인 파일럿이다. Stratus 의 나머지 기법으로 표본을 늘려야
곡선이 나온다.

**단일 계정·합성 로그·짧은 시간 구간.** 실제 침해에서는 warmup 과 detonate 를
같은 주체가 하지 않고, 노이즈 규모도 다르다. 특히 M1 의 IP 일치 조건은 공격자가
다른 단말·프록시를 쓰면 성립하지 않는다.

**모티프 5개가 기법 공간을 대표하지 않는다.** 6개 기법에서 도출했고, 자격증명·
워크로드 중심 기법에 치우쳐 있다. 데이터·네트워크 계층 기법은 다루지 않았다.

**순환 논리를 완전히 제거하지는 못했다.** 모티프를 기법 문서에서 도출했지만, 그
문서 자체가 같은 로그를 보고 작성됐다. 완전히 끊으려면 모티프를 먼저 고정하고
새 로그를 나중에 생성해야 한다.
